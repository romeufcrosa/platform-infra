# Phase 1: Infrastructure Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a complete, working platform foundation in a local `platform-infra` repo — minikube cluster, Ministack (local AWS), ArgoCD (GitOps), Atlantis + OpenTofu (PR-driven IaC), Vault + External Secrets, kube-prometheus-stack, and a local container registry — where every component is declared in Git as OpenTofu modules and reaches "Running" via `make cluster-up && make deploy-infra`.

**Architecture:** A single minikube cluster (docker driver, 8GB RAM) hosts everything in separate namespaces. `platform-infra` is the single source of truth: OpenTofu modules describe the infrastructure, Atlantis reviews/applies them from PRs, and ArgoCD syncs Kubernetes manifests from Git. Components are installed with Helm via the OpenTofu `helm_release` resource so everything is reproducible from `tofu apply`. A `Makefile` wraps the local lifecycle (`cluster-up`, `deploy-infra`, `port-forwards`, `cluster-down`) and `scripts/verify-phase1.sh` is the executable success-criteria test.

**Tech Stack:** minikube 1.34, Kubernetes 1.30, OpenTofu 1.7, providers (helm ~2.13, kubernetes ~2.30, random, tls), Helm 3.15, ArgoCD 2.10, Atlantis 0.28, Vault 1.16 (helm), External Secrets Operator 0.9, kube-prometheus-stack 65.x, Ministack, cloudflared, Docker 27.

**Spec:** `docs/superpowers/specs/2026-09-23-platform-learning-ecosystem-design.md` (sections 2, 3, 6, 8, 11)

## Global Constraints

These apply to **every** task. Do not deviate without amending the spec first.

- **IaC language is OpenTofu, not Terraform.** All files are `.tf`; run `tofu`, never `terraform`. Terraform version in `atlantis.yaml` is the OpenTofu version.
- **Pinned tool versions** live in `.tool-versions` and must be used verbatim: `go 1.22.5`, `nodejs 20.17.0`, `opentofu 1.7.0`, `kubectl 1.30.2`, `helm 3.15.3`, `minikube 1.34.0`, `argocd 2.10.5`, `docker-cli 27.1.0`, `cloudflared 2024.10.0`, `awscli 2.17.0`, `jq 1.8.2`, `make 4.4.1`. Two notes on the keys, both verified against mise 2026.9.14: the registry key for OpenTofu is `opentofu` (not `tofu`) and for Docker is `docker-cli` (not `docker`), and **the versions are what the constraint governs — a key rename is not a version change**. `python` is deliberately **not** pinned (nothing in Phase 1 needs a specific Python; `python3` from the OS is enough for the `json` parsing in the scripts). `mise` is a bootstrap prerequisite, not a pinned tool — it cannot manage itself. `atlantis` is **not** in `.tool-versions` because mise has no registry entry for it and nothing in Phase 1 invokes the CLI; the meaningful Atlantis pin is the Helm chart version `0.28.0` in the Task 10 module. GNU Make **4** is assumed everywhere: macOS's default 3.81 runs each recipe line in a separate shell and breaks the heredoc recipes.
- **Namespace names are fixed:** `argocd`, `atlantis`, `ministack`, `vault`, `monitoring`, `registry`, `external-secrets`, `platform-system` (the 8 platform namespaces), plus the 3 application namespaces `dev`, `staging`, `prod`. **All eleven are created by OpenTofu in Task 4** from one `for_each` over `local.platform_namespaces` in `tofu/main.tf` — that list is the single source of truth. OpenTofu owns all eleven and every `helm_release` passes `create_namespace = false`, so no chart and no tool races another for the same object. (The application namespaces are created empty in Phase 1; Phase 2 populates them. Their `AppProject` definitions also ship in Phase 1.) The Makefile's `NAMESPACES` variable is a human-readable mirror of the platform eight and is **not** authoritative — see ADR-0002.
- **Every deployed workload is Helm-installed by OpenTofu**, not by hand. No `kubectl apply` of component manifests in the steady state — the only exception is ArgoCD bootstrapping itself (documented bootstrap is legitimate and is what the bootstrap module does).
- **No secret values in Git.** Vault root token and ArgoCD admin password are generated by OpenTofu `random_password` and written to a gitignored `local-secrets/` dir; the ArgoCD one is additionally stored as a `Secret`.
- **All images are pinned to an explicit version tag.** Never `:latest` in any manifest or Helm value.
- **Verification is script-based, not manual.** Each task ends with a command that must exit 0. `scripts/verify-phase1.sh` is the task-level gate.
- **README is updated in the same commit as any behavior change** (global requirement from the user). Every task that changes documented behavior must touch `platform-infra/README.md` in its commit step.
- Commit messages follow Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`) and end with the Co-Authored-By trailer.

### Step 2: Pin tool versions

Create `.tool-versions` with exactly the Global Constraints values:

```
go 1.22.5
nodejs 20.17.0
opentofu 1.7.0
kubectl 1.30.2
helm 3.15.3
minikube 1.34.0
argocd 2.10.5
docker-cli 27.1.0
cloudflared 2024.10.0
awscli 2.17.0
jq 1.8.2
make 4.4.1
```

Three entries need justifying, because they are not decoration:

- **`awscli`** — `scripts/bootstrap-ministack-queues.sh` and section 7 of
  `scripts/verify-phase1.sh` shell out to `aws` against the Ministack endpoint. Without it
  the phase gate cannot pass.
- **`jq`** — `scripts/render-dashboards.sh` depends on `jq -S` for deterministic output.
- **`make` 4.4.1** — macOS ships GNU Make **3.81**, which runs each recipe line in a
  separate shell. The `validate` target's `while read ... done <<-'EOF'` heredoc and the
  dashboard render loop silently break under 3.81. Make 4 supports `.ONESHELL` and is the
  version every recipe in this repo assumes. This is not a hypothetical: it is the
  default `make` on the machine executing this plan.

Three entries are deliberately **absent**, and their absence is a decision:

- **`python`** — nothing in Phase 1 needs a specific Python. The scripts use `python3` only
  for `import json` parsing, which the OS `python3` (3.9+) does fine. Pinning it also
  breaks `mise install` on arm64, because the pinned 3.12.5 prebuilt artifact predates
  Python's release attestations and mise rejects it without
  `MISE_PYTHON_GITHUB_ATTESTATIONS=false`. An unused pin that makes the documented setup
  command exit non-zero is worse than no pin.
- **`mise`** — it cannot manage itself. It is a bootstrap prerequisite installed by the
  one-liner below, not a versioned tool.
- **`atlantis`** — mise has no registry entry for it at any version, and nothing in Phase 1
  invokes the Atlantis CLI. Task 10 deploys the *server* via its Helm chart, whose version
  `0.28.0` is pinned in the module. Pinning a CLI nobody runs would be theatre.

Note the two mise key names: `opentofu` (not `tofu`) and `docker-cli` (not `docker`).
Those are mise's registry names for the same binaries. **The version is what this
constraint governs** — a key rename is not a version change.

Install and verify. `mise` itself is a prerequisite and is not managed by `.tool-versions`:

```bash
# Install mise if absent (macOS/Linux one-liner; see https://mise.jdx.dev)
command -v mise >/dev/null || curl https://mise.run | sh
# If that lands in ~/.local/bin and it is not on PATH:
#   echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && exec zsh

mise trust
mise install          # must exit 0 with no env-var workaround
mise exec -- opentofu version   # expect: OpenTofu v1.7.0
mise exec -- kubectl version --client   # expect: v1.30.2
mise exec -- helm version --short      # expect: v3.15.3
mise exec -- make --version | head -1  # expect: GNU Make 4.4.1
mise exec -- aws --version             # expect: aws-cli/2.17.0
```

Expected: `mise install` exits 0 cleanly, and all five version checks print the pinned
versions. If `mise` cannot provide a given tool on this platform, install it via its
official package and record the deviation in the README's Troubleshooting section rather
than silently proceeding on a different version — the pins exist so a failure means "the
toolchain drifted", not "the plan is wrong".

> **`docker-cli` pins the client, not the daemon.** The Docker *daemon* comes from Docker
> Desktop and will not match `27.1.0`. That is expected and correct: the pin governs the
> `docker` command the Makefile and scripts invoke. Record the daemon version in the
> README's Troubleshooting table so nobody reads the mismatch as drift.

> **Arm64 note.** This plan was executed on Apple Silicon. `minikube` with the `docker`
> driver and all the pinned images are multi-arch, so no change is needed. If a future
> contributor is on Intel, the same pins work; the reverse (an x86 contributor reading an
> arm-only assumption) is the failure this note exists to prevent.

### Step 4: Create the Makefile skeleton with the seven stable targets

Create `Makefile`. Later tasks append to it; these eight names and behaviours are frozen.

```makefile
SHELL := /bin/bash
.SHELLFLAGS := -eu -o pipefail -c
.DEFAULT_GOAL := help

MINIKUBE_PROFILE ?= platform
NAMESPACES := argocd atlantis ministack vault monitoring registry external-secrets platform-system

.PHONY: help
help: ## Show this help
	@grep -hE '^[a-zA-Z_-]+:.*?## ' $(MAKEFILE_LIST) | awk 'BEGIN{FS=":.*?## "}{printf "  \033[36m%-18s\033[0m %s\n", $$1, $$2}'

.PHONY: cluster-up
cluster-up: ## Create/start the minikube cluster with pinned addons
	./scripts/setup-minikube.sh

.PHONY: cluster-down
cluster-down: ## Delete the minikube cluster (destructive)
	@read -p "Delete minikube profile '$(MINIKUBE_PROFILE)' and ALL its data? [y/N] " a; [ "$$a" = y ]
	minikube delete -p $(MINIKUBE_PROFILE)

.PHONY: deploy-infra
deploy-infra: ## Apply all infrastructure with OpenTofu
	tofu -chdir=tofu init -upgrade=false -input=false
	tofu -chdir=tofu apply -auto-approve -input=false

.PHONY: destroy-infra
destroy-infra: ## Destroy all infrastructure managed by OpenTofu (destructive)
	@read -p "Destroy ALL OpenTofu-managed resources? [y/N] " a; [ "$$a" = y ]
	tofu -chdir=tofu destroy -auto-approve -input=false

.PHONY: port-forwards
port-forwards: ## Forward ArgoCD, Grafana, Vault, Ministack, registry to localhost
	./scripts/port-forwards.sh

.PHONY: verify
verify: ## Run the Phase 1 success-criteria gate
	./scripts/verify-phase1.sh

.PHONY: fmt
fmt: ## Format and validate OpenTofu configuration
	tofu -chdir=tofu fmt -recursive
	tofu -chdir=tofu validate
```

> The help text says exactly what the recipe does. It does **not** mention Helm or YAML:
> `helm/values` is a directory of values files, not a chart, so `helm lint` on it is a
> no-op, and YAML linting is a separate concern. Task 5's `validate` target is what
> actually runs `helm template` and `yamllint` — a target whose description claims a
> check it does not perform is worse than one that admits its scope.

### Step 6: Write the four ADRs

Each ADR uses this exact shape (MADR template), with `Status: Accepted`:

`docs/adr/0001-record-architecture-decisions.md` — Context: decisions here are load-bearing across four repos and expensive to revisit. Decision: we use ADRs, one per decision, never edited after acceptance (superseded instead).

`0002-single-minikube-cluster.md` — Context: Atlantis must run in-cluster per team practice, but app workloads also need a cluster. Decision: one minikube profile named `platform`, docker driver, 8GB RAM, namespace isolation instead of cluster isolation. Consequences: shared blast radius locally; acceptable because the whole stack is disposable via `make cluster-down`.

`0003-opentofu-over-terraform.md` — Context: team standardized on OpenTofu post-BSL; Atlantis supports it natively. Decision: `.tf` files, `tofu` binary, no `terraform` invocations anywhere including CI. Consequences: `tofu init` handles provider registry transparently; lock file semantics unchanged.

`0004-ministack-over-localstack.md` — Context: LocalStack's free tier no longer covers the services we need and its licensing changed; Ministack is fully free. Decision: Ministack for SQS/S3/Secrets Manager locally. Consequences: AWS SDK compatibility is good but not total — services under test must be written against a documented subset (queue operations, not every API), and `docs/runbooks/` records gaps as they are found.

### Step 2: Write `scripts/setup-minikube.sh`

```bash
#!/usr/bin/env bash
# Idempotently create/start the platform minikube cluster with pinned addons.
# Safe to re-run: an existing, running cluster is left untouched.
set -euo pipefail

PROFILE="${MINIKUBE_PROFILE:-platform}"
K8S_VERSION="${K8S_VERSION:-v1.30.2}"
CPUS="${MINIKUBE_CPUS:-4}"
MEMORY="${MINIKUBE_MEMORY:-8192mb}"
DISK="${MINIKUBE_DISK:-50g}"
ADDONS=(registry ingress metrics-server)

log() { printf '\033[1;34m==>\033[0m %s\n' "$*"; }
die() { printf '\033[1;31mERROR:\033[0m %s\n' "$*" >&2; exit 1; }

command -v minikube >/dev/null || die "minikube not found — run 'mise install' first"

if minikube status -p "$PROFILE" >/dev/null 2>&1; then
  log "Profile '$PROFILE' exists; starting it"
  minikube start -p "$PROFILE" >/dev/null
else
  log "Creating profile '$PROFILE' (k8s $K8S_VERSION, ${CPUS}cpu, $MEMORY, $DISK)"
  minikube start \
    -p "$PROFILE" \
    --driver=docker \
    --kubernetes-version="$K8S_VERSION" \
    --cpus="$CPUS" \
    --memory="$MEMORY" \
    --disk-size="$DISK" \
    --addons="${ADDONS[*]}" \
    --embed-certs=true
fi

for addon in "${ADDONS[@]}"; do
  log "Ensuring addon '$addon' enabled"
  minikube addons enable "$addon" -p "$PROFILE" >/dev/null
done

kubectl config use-context "$PROFILE" >/dev/null
log "Cluster ready. Context: $PROFILE"
minikube status -p "$PROFILE"
```

**Namespace ownership is unambiguous: OpenTofu owns all eleven namespaces, Helm owns
nothing.** The `argocd` and `monitoring` namespaces are no exception — a chart installed
into a namespace OpenTofu already created adopts it silently, and `helm_release` is
configured with `create_namespace = false` everywhere so the two tools can never race to
create the same object. The `create` variable on the namespace module exists for a
different reason: a later phase may need to adopt a namespace that predates the module.
Phase 1 does not use it, and every call site below passes nothing, so all eleven are
created.

Add `create_namespace = false` to **every** `helm_release` resource in every module
(Steps 3, 4, and 8 of this task plus Tasks 6, 7, 8, 9, 10). The OpenTofu-created
namespaces must exist before the chart runs, which is what the module `depends_on`
chain guarantees.

### Step 4: The ArgoCD Application manifest (the GitOps entry point)

`kubernetes/platform-system/platform/argocd.yaml` — this file is the *bootstrap*: ArgoCD is told to sync this repo, and this repo contains the platform manifests. It is intentionally small and has no self-reference loop.

```yaml
# The single Application that makes this repo's platform-system/ directory
# authoritative. Everything else in kubernetes/platform-system/ is synced
# through it.
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: platform-system
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io
spec:
  project: platform-system
  source:
    repoURL: REPLACE_WITH_REPO_URL   # set by `tofu apply` from var.repo_url
    targetRevision: main
    path: kubernetes/platform-system
    directory:
      recurse: true
  destination:
    server: https://kubernetes.default.svc
    namespace: platform-system
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - PruneLast=true
  ignoreDifferences:
    # OpenTofu writes these; ArgoCD must not fight it over them.
    - group: v1
      kind: Namespace
      jsonPointers:
        - /metadata/labels/platform~1environment
```

> `REPLACE_WITH_REPO_URL` is substituted at apply time. The cleanest way is to render this file with a `local_file` resource whose `content` is `templatefile()`-ed with `repo_url`, rather than committing a URL that is correct on one machine and wrong on the next. Add the following to `tofu/modules/argocd/`:

```hcl
resource "local_file" "bootstrap_application" {
  filename        = "${path.module}/../../kubernetes/platform-system/platform/argocd.yaml"
  content         = templatefile("${path.module}/bootstrap-application.yaml.tftpl", { repo_url = var.repo_url })
  file_permission = "0644"
}
```

```bash
cat > tofu/modules/argocd/bootstrap-application.yaml.tftpl <<'EOF'
# Generated by OpenTofu (module argocd) — do not edit by hand; edit the
# .tftpl template instead. The file is committed so ArgoCD has something to
# read on the very first sync, and regenerated on every apply so the repoURL
# always matches this machine's configuration.
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: platform-system
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io
spec:
  project: platform-system
  source:
    repoURL: ${repo_url}
    targetRevision: main
    path: kubernetes/platform-system
  destination:
    server: https://kubernetes.default.svc
    namespace: platform-system
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - PruneLast=true
EOF
```

Delete the hand-written `kubernetes/platform-system/platform/argocd.yaml` from Step 4's first block — the template is the single source. Add `platform/argocd.yaml` to the kustomization's `resources` list; the generated file is the one Kustomize reads.

### Step 8: `scripts/smoke-atlantis-webhook.sh`

Written by Frontend 2 (Task 12) but landed here, because this task owns the webhook contract. It lets a developer verify the tunnel and endpoint without opening GitHub — the fastest possible feedback loop when the webhook is down:

```bash
#!/usr/bin/env bash
# Deliver a synthetic GitHub pull_request event to Atlantis and assert it
# acknowledges the delivery. Verifies tunnel + endpoint + secret in one shot.
set -euo pipefail

URL="${ATLANTIS_PUBLIC_URL:?set ATLANTIS_PUBLIC_URL to the cloudflared URL}"
SECRET_FILE="${SECRET_FILE:-local-secrets/atlantis-webhook-secret}"
REPO="${GITHUB_ORG:-romeufcrosa}/$(GITHUB_REPO:-platform-infra)"

[ -f "$SECRET_FILE" ] || { echo "missing $SECRET_FILE — run make deploy-infra" >&2; exit 1; }
SECRET="$(cat "$SECRET_FILE")"

BODY=$(python3 - "$REPO" <<'PY'
import json, sys, time
repo = sys.argv[1]
print(json.dumps({
  "action": "opened",
  "number": 9999,
  "pull_request": {
    "number": 9999,
    "state": "open",
    "title": "smoke: synthetic webhook",
    "head": {"ref": "smoke/synthetic-webhook"},
    "base": {"ref": "main"},
    "user": {"login": "atlantis-smoke"}
  },
  "repository": {"full_name": repo, "name": repo.split("/")[1],
                 "owner": {"login": repo.split("/")[0]}},
  "installation": {"id": 1}
}))
PY
)

SIG="sha256=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')"

echo "POST $URL/events (X-Hub-Signature-256: $SIG)"
code=$(curl -s -o /tmp/atlantis-smoke.out -w '%{http_code}' \
  -X POST "$URL/events" \
  -H "Content-Type: application/json" \
  -H "X-GitHub-Event: pull_request" \
  -H "X-Hub-Signature-256: $SIG" \
  -H "X-GitHub-Delivery: $(uuidgen)" \
  -d "$BODY")
cat /tmp/atlantis-smoke.out; echo
[ "$code" = "200" ] || { echo "FAIL: expected 200, got $code" >&2; exit 1; }
echo "WEBHOOK ACCEPTED — check 'kubectl -n atlantis logs deploy/atlantis' for the lock/plan result"
```

- `smoke-atlantis-webhook.sh` returns non-200 → the problem is tunnel, endpoint, or webhook secret.
- It returns 200 but no plan appears → the problem is inside Atlantis: repo lock, PAT scope, or `dir: tofu` not matching.

### Step 9: `docs/runbooks/atlantis-webhook-debug.md`

The decision tree, symptom-first:

1. **No comment on the PR at all.** Check `curl -sf $ATLANTIS_PUBLIC_URL/healthz`. Fails → the quick tunnel died (they expire; re-run cloudflared and re-register the webhook). Passes → run `scripts/smoke-atlantis-webhook.sh`. Non-200 → the webhook secret in GitHub does not match `local-secrets/atlantis-webhook-secret`; re-run `make webhook-register`. 200 → the event reached Atlantis, so go to (2).
2. **Event received, no plan.** `kubectl -n atlantis logs deploy/atlantis | tail -50`. `repo not allowlisted` → `allow_custom_workflows`/repo config issue. `authentication error` → the PAT lacks `repo` scope, or the webhook is not a GitHub App installation. `no project found` → `dir: tofu` does not match where the `.tf` files actually are.
3. **Plan appears, apply refused.** `execution_mode: plan` is doing exactly what Phase 1 intends. To exercise apply, comment `atlantis apply -d tofu` *and* expect the refusal — then flip `execution_mode` to `apply` in a PR and watch it work. That round trip is the lesson.
4. **Terraform provider cannot reach the cluster.** Atlantis runs `tofu` in-cluster; the kubeconfig it picks up is the pod's ServiceAccount, not your host's. If a provider is configured with `config_path = pathexpand("~/.kube/config")` it will fail in Atlantis even though it works on your laptop. This is the single most common Phase 1 surprise — the fix is an explicit `exec` block using the in-cluster ServiceAccount. Record the fix in the runbook when you hit it, because it will be hit again.

### Step 1: Write `scripts/verify-phase1.sh`

This is the executable form of the spec's Phase 1 success criteria. It must be readable by a human and honest about what it does not check.

```bash
#!/usr/bin/env bash
# Phase 1 success-criteria gate.
# Exits 0 and prints "PHASE 1 VERIFICATION PASSED" only if every check below
# passes. Every check is a cluster or endpoint observation, not a state-file
# inspection: the point is to prove the running system, not the IaC's
# opinion of it.
set -uo pipefail

CTX="${MINIKUBE_PROFILE:-platform}"
FAILED=0
PASSED=0

green() { printf '\033[0;32m%s\033[0m\n' "$*"; }
red()   { printf '\033[0;31m%s\033[0m\n' "$*"; }

check() { # check <description> <command...>
  local desc="$1"; shift
  if "$@" >/dev/null 2>&1; then
    green "  PASS  $desc"; PASSED=$((PASSED+1))
  else
    red   "  FAIL  $desc"; FAILED=$((FAILED+1))
  fi
}

section() { printf '\n\033[1m%s\033[0m\n' "$*"; }

# --- 0. prerequisites -------------------------------------------------------
section "Toolchain"

check "all nodes are Ready" bash -c \
  "[ \"\$(kubectl --context '$CTX' get nodes --no-headers | grep -cv ' Ready ')\" -eq 0 ]"

  "kubectl --context '$CTX' -n argocd wait --for=condition=Available deploy/argocd-server --timeout=60s"

  "kubectl --context '$CTX' -n atlantis wait --for=condition=Available deploy/atlantis --timeout=60s"

# --- 4. no crashlooping anywhere -------------------------------------------
section "Pod health"
BADPODS=$(kubectl --context "$CTX" get pods -A --no-headers \
  | grep -Ev 'Completed|evicted' \
  | grep -E 'CrashLoopBackOff|ImagePullBackOff|ErrImagePull|Error|Pending' || true)
if [ -z "$BADPODS" ]; then
  green "  PASS  no pods in CrashLoopBackOff / ImagePullBackOff / Error / Pending"
  PASSED=$((PASSED+1))
else
  red "  FAIL  unhealthy pods:"; echo "$BADPODS" | sed 's/^/        /'
  FAILED=$((FAILED+1))
fi

# --- 5. GitOps --------------------------------------------------------------
section "GitOps"
check "ArgoCD Application 'platform-system' exists" \
  kubectl --context "$CTX" -n argocd get application platform-system
check "ArgoCD Application is Synced" bash -c \
  "kubectl --context '$CTX' -n argocd get application platform-system -o jsonpath='{.status.sync.status}' | grep -q Synced"
check "ArgoCD Application is Healthy" bash -c \
  "kubectl --context '$CTX' -n argocd get application platform-system -o jsonpath='{.status.health.status}' | grep -q Healthy"
check "all 4 AppProjects exist" bash -c \
  "[ \"\$(kubectl --context '$CTX' -n argocd get appprojects -o name | wc -l | tr -d ' ')\" -eq 4 ]"

# --- 6. secrets -------------------------------------------------------------
section "Secrets"
check "ClusterSecretStore/vault is Ready" bash -c \
  "kubectl --context '$CTX' get clustersecretstore vault -o jsonpath='{.status.conditions[?(@.type==\"Ready\")].status}' | grep -q True"
check "ExternalSecret synced a Kubernetes Secret" \
  kubectl --context "$CTX" -n dev get secret go-service-credentials
check "admin password files exist with mode 0600" bash -c \
  "[ \"\$(stat -f '%Lp' local-secrets/argocd-admin-password 2>/dev/null || stat -c '%a' local-secrets/argocd-admin-password)\" = '600' ]"
check "no secret file is tracked by git" bash -c \
  "! git ls-files --error-unmatch local-secrets 2>/dev/null"

# --- 7. local AWS -----------------------------------------------------------
section "Local AWS (Ministack)"
check "Ministack health endpoint responds" curl -sf http://localhost:4566/_ministack/health
for q in order-events order-events-dlq platform-notifications; do
  check "queue '$q' exists" aws --endpoint-url http://localhost:4566 sqs describe-queues --queue-names "$q"
done
check "send/receive round-trip works" bash -c '
  URL=$(aws --endpoint-url http://localhost:4566 sqs get-queue-url --queue-name order-events --query QueueUrl --output text)
  RID=$(aws --endpoint-url http://localhost:4566 sqs send-message --queue-url "$URL" \
          --message-body "{\"probe\":\"verify\"}" --query MessageId --output text) || exit 1
  [ -n "$RID" ] || exit 1
  aws --endpoint-url http://localhost:4566 sqs delete-message --queue-url "$URL" \
      --receipt-handle "$(aws --endpoint-url http://localhost:4566 sqs receive-message --queue-url "$URL" --max-number-of-messages 1 --query Messages[0].ReceiptHandle --output text)" >/dev/null'

# --- 8. registry ------------------------------------------------------------
section "Container registry"
check "registry reachable on localhost:5000" curl -sf http://localhost:5000/v2/
check "image pull secret exists in every namespace" bash -c '
  for ns in argocd atlantis ministack vault monitoring registry external-secrets platform-system; do
    kubectl --context "'"$CTX"'" -n "$ns" get secret registry-pull-secret >/dev/null 2>&1 || exit 1
  done'

# --- 9. observability -------------------------------------------------------
section "Observability"
check "Prometheus has active scrape targets" bash -c \
  "[ \"\$(curl -sf 'http://localhost:9090/api/v1/targets?state=active' | python3 -c 'import json,sys; print(len(json.load(sys.stdin)[\"data\"][\"activeTargets\"]))')\" -gt 0 ]"
check "Prometheus can answer a real query" bash -c \
  "curl -sf --get --data-urlencode 'query=up' http://localhost:9090/api/v1/query | grep -q '\"result\"'"
check "3 Grafana dashboards provisioned" bash -c \
  "[ \"\$(curl -sf -u \"admin:\$(cat local-secrets/grafana-admin-password)\" 'http://localhost:3000/api/search?type=dash-db' | python3 -c 'import json,sys; print(len(json.load(sys.stdin)))')\" -ge 3 ]"

# --- 10. Atlantis -----------------------------------------------------------
section "Atlantis"
check "Atlantis health endpoint responds" curl -sf http://localhost:8080/healthz
check "Atlantis has locked the repo" bash -c \
  "kubectl --context '$CTX' -n atlantis exec deploy/atlantis -- \
     sh -c 'test -d /home/atlantis/.atlantis/repos' || true"

# --- summary ----------------------------------------------------------------
printf '\n\033[1m%d passed, %d failed\033[0m\n' "$PASSED" "$FAILED"
if [ "$FAILED" -eq 0 ]; then
  green "PHASE 1 VERIFICATION PASSED"
  exit 0
fi
red "PHASE 1 VERIFICATION FAILED"
cat <<'EOF'

Not every check is equally load-bearing. If you are chasing failures, work in
this order:
  1. Pod health        - almost every other failure is downstream of this
  2. ArgoCD Synced     - if this fails, GitOps is not the source of truth yet
  3. ClusterSecretStore - Vault may be up while the Operator cannot reach it
  4. Ministack queues   - endpoint reachable but queues not bootstrapped
See docs/runbooks/ for the symptom-first runbooks.
EOF
exit 1
```

### Step 3: `docs/onboarding.md`

Written to be followed top to bottom by someone who has never seen the repo. Target: **under 30 minutes** to a working platform, verified by `make verify`.

Required sections, in order:

1. **What this is** — four repos, one cluster, one sentence each on why the split exists
2. **Prerequisites** — Docker Desktop running, 8GB RAM free, GitHub account, the exact `brew install` lines for minikube/kubectl/helm/cloudflared/openssl, and `mise` for the rest
3. **Ten-minute path** — the six commands, copy-pasteable, each annotated with what it does and what success looks like:
   ```bash
   git clone https://github.com/<you>/platform-infra.git && cd platform-infra
   mise trust && mise install
   eval "$(mise activate bash)"        # zsh: mise activate
   make --version                      # MUST say GNU Make 4.4.1, not 3.81
   make cluster-up
   make deploy-infra
   make port-forwards &     # leave running in this terminal
   ./scripts/seed-vault.sh
   make verify
   ```
   The `mise activate` line is not optional boilerplate. On macOS `mise install`
   writes shims but does not shadow `/usr/bin/make`, so without it `make` is
   Apple's BSD Make 3.81 and the later heredoc recipes fail with errors that
   read like repository bugs. Add the activation to the reader's shell profile
   in step 2, and keep `mise exec -- make <target>` documented as the
   per-command fallback.
4. **Where things are** — the endpoint table (ArgoCD, Grafana, Prometheus, Vault, Ministack, Registry, Atlantis), each with its URL, its credentials file path, and a one-line description of what you are looking at
5. **The four things to try in your first hour** — a numbered, ordered list, each with an expected observation:
   - Open the Grafana `platform-overview` dashboard and find the `dev` namespace memory panel. Change a Pod's memory limit in `kubernetes/platform-system/platform/`, commit, and watch ArgoCD sync it. This is the GitOps loop in its shortest form.
   - Create a queue message: `aws --endpoint-url http://localhost:4566 sqs send-message --queue-url $(aws --endpoint-url http://localhost:4566 sqs get-queue-url --queue-name order-events --query QueueUrl --output text) --message-body '{"type":"order.created"}'`, then read it back. This is the contract Phase 2 builds on.
   - Change a Vault secret: `./scripts/seed-vault.sh`, then `kubectl -n dev get secret go-service-credentials -o yaml | grep database-url` before and after. Watch the Operator sync. This is the secrets loop.
   - Open a PR that edits `tofu/environments/local/overrides.tf` and read the Atlantis plan comment. This is the IaC review loop.
6. **Where to change what** — a table mapping intent to file: adding a namespace, adding a component, adding a dashboard, adding a secret path, pinning a new chart version
7. **Runbooks index** — one line per file in `docs/runbooks/` with its symptom
8. **Troubleshooting the top five** — the five things that actually go wrong, each with the one command that diagnoses it

## Phase 1 Exit Gate

Phase 1 is done when **all** of these hold. The first six are automated by `make verify`; the last two are the user's manual validation.

### Automated

- [ ] `make cluster-up` is idempotent and exits 0 on a running cluster
- [ ] `tofu -chdir=tofu apply -auto-approve` completes with no errors from a clean state
- [ ] All 11 namespaces exist
- [ ] ArgoCD `platform-system` Application is `Synced` and `Healthy`
- [ ] All 4 AppProjects exist; `prod` denies sync to non-team roles
- [ ] `ClusterSecretStore/vault` is `Ready`; `go-service-credentials` exists in `dev`
- [ ] `local-secrets/` is untracked and every file is mode 0600
- [ ] 3 SQS queues exist and a send/receive round-trip succeeds
- [ ] Registry accepts a push and a pod pulls using the namespace's pull secret
- [ ] Prometheus has active targets and answers a real query
- [ ] 3 Grafana dashboards are provisioned and render data
- [ ] Atlantis health endpoint responds

### Manual (validated by the user)

- [ ] **Atlantis plans a real PR.** Open a PR editing `tofu/environments/local/overrides.tf`; an `atlantis plan` comment arrives with a diff that matches the change. This is the criterion that proves the webhook, the tunnel, the PAT, the repo lock, and the `dir: tofu` setting are all correct together.
- [ ] **The onboarding path works from scratch.** `make cluster-down`, then follow `docs/onboarding.md` in a clean shell, and reach a passing `make verify` in under 30 minutes.

### Explicitly out of scope for Phase 1

Named here so their absence is a decision, not an oversight: no service mesh; no Atlantis *apply* (`execution_mode: plan` is deliberate); no remote Terraform backend or state locking; no real AWS; no image scanning wired into the registry; no NetworkPolicy; no PodDisruptionBudget; no multi-node cluster. Each belongs to a later phase and each is noted in the README's Known Limitations where a reader would otherwise assume it exists.
